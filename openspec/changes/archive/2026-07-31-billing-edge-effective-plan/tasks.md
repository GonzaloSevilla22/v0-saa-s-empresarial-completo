## Nota — deviación encontrada post-implementación (checks del PR, no TDD)

El primer push del PR #316 pasó `validate-kpis` (gates SQL) pero **falló el check `Vercel`** (build de producción de `frontend/`, distinto del runner de `pnpm vitest run`): `npx next build` SÍ type-chequea con `tsc`, y como `frontend/__tests__/ai-quota.test.ts` importa el archivo real `supabase/functions/_shared/ai-quota.ts` (D6), el compilador de Next.js quedó alcanzando transitivamente ese archivo — y su `import ... from "./effective-plan.ts"` (extensión `.ts` explícita, **obligatoria** en Deno para imports relativos) no es válida para `tsc` salvo que se habilite `allowImportingTsExtensions`. `vitest` no lo detectó porque usa esbuild para transpilar sin chequear tipos. Verificado con `pnpm run build` local (91 rutas, compila limpio) antes de re-empujar. **Lección para el registro de skills/CI**: D6 hace correcto asumir "no hay harness de Deno", pero un import real entre dos archivos de `supabase/functions/` que además es alcanzado por un test de `frontend/` SÍ queda bajo el `tsc` de Next.js — verificar `pnpm run build` (no solo `pnpm vitest run`) antes de abrir PR cuando un test importa un archivo real fuera de `frontend/`.
